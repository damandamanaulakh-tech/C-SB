# Phase-2 Example Layer

## Active parameter baseline

All new Human-derived functional examples use the active successor registry:

`SB-HFR-P0001..SB-HFR-P3204` = 3,204 Human-derived functional source parameters.

`SB-ASI-P0001..SB-ASI-P2560` remains immutable legacy provenance. Older examples that say "existing 2,560" are historical examples and must not be copied forward as the active count.

The effective source count is 3,204, not 5,764. The successor source does not imply that all 3,204 parameters are HUMAN_PHYSICAL. Runtime ownership remains separately classified under `HUMAN_PHYSICAL`, `BRAIN_COGNITIVE`, `AFFECT_RELATIONAL`, `SEQUENCE_RUNTIME`, `MIXED`, or `UNKNOWN`.

## Counting law

Example counts must keep these categories separate:

- Existing 3,204 source activations do not create new parameters.
- Runtime relations are not parameters.
- Interpretation candidates are not parameters.
- Pattern candidates are not approved patterns.
- Rubric/rule candidates are not canonical rubrics.
- User approval does not mutate a closed source record; it creates a versioned write-back/new Sequence.

Container-level activation may be shown when source evidence supports the container. Exact `SB-HFR-Pxxxx` atomic IDs may only be asserted after exact registry lookup; never infer an atomic parameter meaning from a container title alone.
